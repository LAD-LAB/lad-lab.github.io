The state of things when I arrived

What existed

  • Pipeline-to-Phyloseq R scripts for single-marker runs (trnL or 12S processed separately)
  • Manual scp to get files from DCC
  • Taxonomy via taxonomizr + 70 GB SQL database on Isilon
  • Missing accessions required manual lookup and hardcoded fixes
  • A megaphyloseq that hadn’t been updated in nearly two years
  • No central bioinformatics documentation (wet lab protocols existed)

What didn’t exist

  • Multiplex support (trnL + 12S pooled in one run)
  • An automated way to build the megaphyloseq
  • Common name assignment beyond manual curation
  • Human read anonymization for SRA deposition
  • PacBio 16S pipeline
  • A bioinformatics documentation website
To set the stage: the core pipeline existed when I arrived and it worked well for single-marker runs. Taxonomy used the taxonomizr package with a 70-gig SQL database on Isilon. The megaphyloseq hadn't been updated in a while because there hadn't been a need. On the documentation side, the wet lab protocols were solid, but there wasn't a central place for the bioinformatics workflow. Rewriting
the Pipeline

Building for the multiplex era

Pipeline-to-Phyloseq: before and after

Before

  • One marker at a time
  • Manual scp from DCC
  • Manual QZV unzipping for read counts
  • 70 GB SQL database on Isilon
  • Manual accession lookups for missing taxa
  • Required familiarity with the specific scripts to run
→

After

  • Handles multiplexed runs natively (trnL + 12S from one pooled run)
  • Automated rsync with staging directory
  • Programmatic read count extraction
  • Custom taxonomy functions in foodseq.tools, no Isilon SQL dependency
  • Template format: change a few variables and run
  • Built-in validation, QC plots, and documentation

The move to multiplex sequencing was the driving force; the existing code was designed for single-marker runs and wasn’t set up to handle trnL and 12S pooled together, which motivated a rewrite.

The move to multiplex sequencing was what motivated the rewrite. The existing code worked well for single-marker runs but wasn't set up for the case where trnL and 12S come from one pooled run. The biggest change under the hood was the taxonomy functions: assignment_trnL does exact sequence matching against the reference FASTA and condenses multi-match ASVs, while assignment_12S uses a naive Bayesian classifier. Both are in the foodseq.tools package, and they eliminated the dependency on the 70-gig SQL database on Isilon that the old taxonomizr-based approach required.

The journey of a sequencing run

Here's the full data flow. Raw data comes off the sequencer, gets transferred to DCC, and forks into the trnL and 12S QIIME2/DADA2 pipelines running in parallel. Everything on the right is Pipeline-to-Phyloseq, which is what I built. It picks up the output from both markers, assigns taxonomy, runs QC, and produces the final phyloseq object.

In October 2025, I presented on the megaphyloseq problem. The trnL megaphyloseq hadn't been updated in two years, and the 12S one had never existed. To fix that I built Isilon-to-Phyloseq, which automates the entire flow from Isilon to DCC to Box to merge. We now have 103 runs and over 31,000 samples across both markers. It has automated changelog tracking and Google Sheets logging, and it prevents duplicates.

Cross-study PCA of the trnL megaphyloseq

This is a PCA of the trnL megaphyloseq following the handbook workflow: NAs filtered at the superkingdom level, CLR-transformed via microbiome::transform, then prcomp with centering. ASVs are glommed by common name, bringing 557 assigned ASVs down to 397 taxa. Project names were pulled from the lab's project tracker sheet and subsampled to about 150 per project. You can see Cebu and DOST, both Filipino cohorts, separating upward, and DFC pulling downward. The loading arrows show which foods drive the separation: rice, brassicas, wheat/rye, bananas, and apiaceae.

Cross-study PCA of the 12Sv5 megaphyloseq

Same approach for the 12Sv5 megaphyloseq, which is the first one this lab has ever had. Human and synthetic ASVs are filtered out, and ASVs are glommed by species, bringing 3,027 ASVs down to 1,136 taxa. PC1 explains 31.1% and PC2 explains 16.7%. The loading arrows show chicken, pork, and cattle as the main drivers of variation. This object didn't exist until a few months ago, and these are the first cross-study analyses anyone has done with it.

This is one example of the kind of question the megaphyloseq lets us investigate. We have 26 ASVs assigned to elk in the 12S data, four of which appear in more than one sample. The heatmap shows where those four elk ASVs are detected across projects, with the top human ASV shown at the bottom for comparison. Elk ASV 1, the most prevalent one, shows up in 394 samples across every single project. You can compare its distribution to the human ASV in the bottom row and see how similar the pattern is. How similar are the elk ASVs to human?

This is the sequence-level view. Each row is one of the four elk ASVs aligned against its closest human ASV by hamming distance. Gray is a match, red is a mismatch. Elk ASV 1, the one in 394 samples, differs from its closest human sequence by only 9 SNPs across around 100 base pairs. Elk ASV 4, in 6 samples, is only 1 SNP away. So we have two pieces of evidence to consider together: the cross-cohort distribution from the heatmap and the sequence similarity here. I'd be curious what the group thinks is going on. Either way, this is the kind of question the megaphyloseq makes it possible to ask, since you wouldn't notice it looking at one study at a time.

The Human Read
Anonymizer

A recurring theme across my presentations

The anonymizer over time

This tool has appeared in every one of my presentations. Here’s the progression:

May 2025
Version 1: list-based matching against known human ASVs. Four-day runtimes, broken job arrays, mismatched paired files, and human reads slipping through.

“Currently, running the code on SEEM takes about four days; unreasonably high runtimes make the tool impractical.”

— me, May 2025, slide 11

Oct 2025
Version 2: switched to a k-mer matching approach (inspired by translating Ben Callahan’s C++ code). Detection was better, but replacement sequences were getting filtered by DADA2 (116 ASVs existed only pre-filtering, 45 only post-filtering).
Feb 2026
Version 3: primer-aware replacement with preserved quality scores and fixed SNP positions. trnL data fully intact; 12S denoising issue resolved.
Now
Documented on the handbook with HPC batch processing scripts, built-in verification, and a full explanation of the detection and replacement logic.
The anonymizer has been a constant thread through my presentations. In May 2025, my first attempt used list-based matching, took four days to run, and the job arrays didn't work. By October, I'd rewritten it with k-mer matching, which improved detection but introduced DADA2 artifacts. By February, version 3 with preserved quality scores and fixed SNP positions was working. And now it's fully documented on the handbook.

Common Name
Assignment

Turning Latin binomials into dietary names

assign_common_names()

“Common Names Assignment: This has been on my back-burner for a year now, but I need to manually fill in the common names CSVs at some point.”

— me, October 2025, slide 36

I presented the details of this in February, so I’ll keep it brief. The core problem is that a single ASV can match dozens of species across multiple genera, and you need a concise dietary name, not a list of Latin binomials.

Since the February presentation

  • Function is documented on the handbook with downloadable R code and the trnL common names CSV
  • 301 trnL ASVs processed from the megaphyloseq; 79% resolve with no conflicts
  • Still needs wider testing by others in the lab

A few example outputs as a reminder

I went into a lot of detail on this in February, so I won't repeat all of it. The short version is that the function resolves multi-species ASV matches into concise dietary names through a hierarchy of conflict resolution strategies. It's worth mentioning that I first tried to use AI to assign common names back in December 2024, but it hallucinated too often to be reliable, which is what eventually led me to build the rule-based system instead. It's documented on the handbook, and the R code and CSV are available for download. The main thing it still needs is testing by other people in the lab.

PacBio 16S
Pipeline

Full-length microbiome sequencing

PacBio 16S pipeline

“This summer, Auri’s 16S run of cecum and colon samples from mice having undergone colostomies and sham surgeries completed, but I have been having a lot of trouble completing the run, partly due to the size of the files.”

— me, October 2025, slide 24

What it includes

  • DADA2 pipeline for PacBio HiFi long reads (~1500 bp), adapted from existing code
  • PacBioErrfun error model (not Illumina defaults)
  • GreenGenes2 taxonomy at species level
  • 32 CPUs, 256 GB RAM on DCC via SLURM
  • Singularity container for reproducibility
  • Intermediate RDS saves for crash recovery

Why it matters

  • trnL / 12S → what subjects eat
  • 16S → the gut microbiome
  • Together → diet–microbiome relationships

This is a separate workflow from the dietary markers, and 16S is out of scope for the FoodSeq paper, but the pipeline exists and is documented on the handbook.

Auri's PacBio run is what necessitated the 16S pipeline. I was struggling with the file sizes for months. A lot of the code was derived from work by Dr. Callahan, Eva, and Mengyi, and I want to make sure they get credit for that. The result is a full DADA2 pipeline calibrated for PacBio HiFi reads, running on DCC with GreenGenes2 taxonomy. It's separate from the dietary metabarcoding work, since 16S captures the microbiome rather than the diet, but it complements trnL and 12S for studying diet-microbiome relationships. It's documented on the handbook and the R script is available for download.

The FoodSeq pipeline paper

The FoodSeq pipeline paper

A methods/resource paper on the pipeline and curated reference database for dietary DNA profiling, led by Anna and to be written over the coming months as a group effort.

What it is

  • Not a software paper; the database, curation logic, and biological validation are central
  • Framed analogously to QIIME 2 or GATK for standardizing dietary metabarcoding
  • Seven published papers already use FoodSeq, and four provide independent validation

Why it’s possible now

  • The handbook documents the methods core
  • Published validation means we don’t start from zero
  • The pipeline is stable and in use across 103 runs and 31,000+ samples

How my work feeds in

  • Pipeline-to-Phyloseq → pipeline overview, implementation
  • Taxonomy functions → workflow architecture, resolution logic
  • Common names → outputs and user-facing reports
  • Anonymizer → implementation, ethics
  • Reference database docs → database construction
  • SQL backbone docs → taxonomy backbone
  • Megaphyloseq (103 runs, 31K+ samples) → scalability evidence
  • The handbook itself → user-facing tutorial

Most of what I’ve built maps to a specific section of the paper.

All of this work is heading toward the FoodSeq pipeline paper. It's a methods/resource paper where the database, curation logic, and biological validation are the central contributions. The reason it's feasible to write it now is that the handbook documents the methods, the published corpus provides validation, and the pipeline has been tested across 103 runs.
